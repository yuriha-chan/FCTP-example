# Foundation API and verification handoff

## Scope and status

This is a bounded summary of the existing seven-package foundation, based on its exports and `tests/foundation.test.ts`. The broad implementation task was interrupted; no Territory A/B application work exists. This foundation is not production-ready, and the checks below do not establish full FCTP protocol compliance.

## Public contracts and typical call sequence

- **`@fctp/protocol`** exports structural FCTP types (`FCTPActor`, `Territory`, `Route`, cargo and vessel models, entry/exit events, listings, maps, token declarations), `validateModel<T>(value, model): ValidationResult<T>`, `assertModel<T>(value, model): T`, `validateInstant(value): boolean`, `validateProduction(production): ValidationIssue[]`, `compareCargo(left, right): CargoDifference`, and `quantityMass(manifest, varietyMass): number`. Validation returns cloned accepted input and allows extension fields. Cargo comparison reports differences; it does not reconcile inventory.
- **`@fctp/identity`** exports context constants, `createLocalDocumentLoader(documents?)`, `withDocuments(loader, documents)`, `generateActorKey(actorId)`, `signJsonLd(document, keyPair, loader)`, `verifyProofCryptography(document, loader)`, `verifyKeyAttribution(document, publisher, loader)`, `checkExpectedIssuer(publisherId, expectedIssuer)`, `checkExitEvidenceBinding(exit, expected)`, `resolveActor(uri, fetcher?)`, `resolveWebFinger(handle, fetcher?)`, and `webFingerSubject(actor)`. Typical signing flow: generate actor key → add its public key method to the publisher’s published key set → make that key document available through a local loader → sign → separately verify cryptography, key attribution, and expected publisher/issuer as required. Actor resolution fetches and checks document ID; WebFinger resolves a self link then resolves the Actor.
- **`@fctp/auth`** exports `encodeNativeToken(bytes)`, `decodeNativeToken(token)`, `deriveDiplomaticToken(nativeToken, resourceServerActorId)`, `digestDiplomaticToken(token)`, `createTokenDigest(actor, revision, token)`, `createTokenRevoke(actor, revision)`, and `TokenCredentialStore`. Store calls: `apply(declaration)` returns `applied | stale | duplicate | conflict`; `get(actor)`, `authenticate(actor, token)`, `snapshot()`, and `restore(snapshot)` manage state. Equal-revision disagreement moves the actor to conflicted state; revoked/conflicted credentials do not authenticate.
- **`@fctp/resources`** exports `ResourceClient(fetcher?)`, `ResourceError`, `territoryResourceUris(actor)`, `selectMapRepresentation(descriptor, supportedFormats)`, and `fetchMapRepresentation(client, descriptor, formats, options?)`. `ResourceClient.get<T>(uri, { token?, accept?, signal?, cache? })` returns `{ value, etag?, notModified }`; `collection<T>(uri, options?)` asynchronously yields pages’ ordered/items and follows `next`; `clearCache()` clears its in-memory cache. `get` uses bearer auth when supplied and includes the token and Accept value in its cache key.
- **`@fctp/client-sdk`** exports `FctpClient(options?)` and `createFctpClient(options?)`. Methods are `resolveActor(uri)`, `resolveWebFinger(handle)`, `get<T>(uri, options?)`, `getActorResource<T>(actor, resourceName, options?)`, and `compareManifests(registry, territory)`. Supply `nativeToken` with `resourceServer` Actor ID to derive a resource-scoped diplomatic token; absent a native token, `get` can use `token` directly.
- **`@fctp/federation`** exports `createActivity(input)`, `parseActivity(value)`, `inferActivityType(object)`, `deliverActivity(activity, inbox, fetcher?)`, and Activity types. Create wraps a cloned object with ActivityStreams/FCTP contexts, actor, recipients, and published time; parse checks the basic envelope; delivery POSTs Activity JSON and reports accepted only for HTTP 202.
- **`@fctp/server-base`** exports `FctpServer`, `JsonSnapshotStore`, `emptyStoreState`, `requireAdmin`, `createCredentialStoreFromSnapshot`, and related state/handler types. Construct with `{ storeFile, fetcher?, verifyInbound?, authorizeAdmin?, authorizeResource?, signActivity?, corsOrigin? }`, then call `open()`. Register Actor documents with `registerActor({ actor, document? })`; register activity handlers with `on(actorId, objectType, handler)`, which returns an unregister function. `receive(localActorId, activity)` queues/deduplicates addressed activity; `processInbox(limit?)` verifies and dispatches queued work. `publish(...)` or atomic `commit(domainMutation, outgoing?)` signs/enqueues outbound work; `processOutbox(limit?)` delivers due items. These worker methods are explicit calls, not automatically scheduled. Register resources with `registerResource(id, body, { public?, actorId? })`; `listen(port?, host?)` returns the chosen port and an async `close()` function. Also available: `enrollPlayer`, `applyTokenDeclaration`, `authenticateDiplomaticToken`, `addRoute`, and `checkAdmin`.
- **Store contract:** `JsonSnapshotStore(file)` provides `open()`, cloned-state `read(reader)`, and serialized durable `transaction(operation)`. State is persisted as an atomically renamed JSON snapshot with file mode `0600`; it contains actor/object data, inbox hashes/queue, outbox/archive, credentials, enrollments, and domain state.

## Security defaults and boundaries

- Server defaults deny admin authorization, deny resource authorization, reject inbound verification (reporting cryptographic verification false), and fail outbound signing until `signActivity` is configured. Protected registered resources default to public unless `{ public: false }` is set. Private resource access requires a bearer token and an allowing `authorizeResource` callback after credential authentication.
- Applying a token declaration checks that the sender is the enrolled Home for that player; inbound token declarations additionally require positive cryptographic, attribution, and expected-issuer report fields. Tokens are stored as digests; native tokens are transformed into resource-Actor-scoped HMAC diplomatic tokens by the SDK/auth helpers.
- Identity has an allowlisted local document loader for built-in contexts; unknown documents fail unless supplied. Proof cryptography, key attribution, expected issuer, and exit evidence binding are separate checks; callers must compose these checks where their policy requires them.
- Resource fetches use `cache: 'no-store'`; local client cache keys separate bearer tokens and Accept headers and honor server `no-store`. The server returns private `no-store` for private resources. Default CORS origin is `*`.

## Verified status and test boundary

| Command | Result |
| --- | --- |
| `npm run typecheck` | Passed (`tsc -b --pretty false`, exit 0) |

The seven foundation tests exercise extension-preserving model validation and descriptive cargo comparison; token byte derivation and revision conflicts/revocation; real `eddsa-rdfc-2022` sign/verify, attribution, tamper detection, and selected WebFinger behavior; bearer-separated resource caching, one HTTP error mapping, and map format selection; basic Activity wrapping/parsing; persistent inbox deduplication/conflicting-ID detection and outbox retry with stable signed payload; and Home-enrolled protected-resource token access. These are focused tests of selected behaviors, not comprehensive API tests or proof of full protocol conformance. They do not verify production workflows, territory policy, end-to-end multi-territory exchange, complete transport interoperability, or all failure/security cases.
